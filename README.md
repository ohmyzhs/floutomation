# Flow Batch Studio

Google Flow 프로젝트에서 이미지 프롬프트를 순차 실행하는 Manifest V3 사이드패널 Chrome 확장입니다. 현재 버전은 `0.6.6`입니다.

Markdown, 일반 텍스트, 캐릭터가 포함된 Flow 전용 문서에서 프롬프트 작업을 분석합니다. 전용 문서에서는 캐릭터 참조 이미지를 먼저 생성·등록하고, 장면 프롬프트의 `@key`를 Flow의 실제 캐릭터 참조 토큰으로 연결한 뒤 이미지 생성을 시작합니다.

- 모델: `Nano Banana Pro`, `Nano Banana 2`, `Nano Banana 2 Lite` 중 선택 (기본값 `Nano Banana 2`)
- 화면비: `16:9`
- 출력 수: 프롬프트당 `2장`
- 작업 간격: 앞 작업의 완료 확인 후 `최소 60초`

큐와 진행 상태는 `chrome.storage.local`에 저장됩니다. 사이드패널을 닫거나 서비스 워커가 잠들어도 유지되며, 캐릭터 생성 단계와 장면 생성 단계 모두 중단 후 이어서 실행할 수 있습니다.

큐가 실행 중이거나 다음 작업을 기다리는 동안에는 Chrome의 `power` API를 `display` 단계로 유지하여 macOS의 유휴 화면 꺼짐·자동 잠금·시스템 절전을 방지합니다. 큐를 중단하거나 완료하면 즉시 해제하며, 프로젝트 ZIP 다운로드 중에도 유지합니다. 사용자가 직접 **화면 잠금**을 누르거나 맥북 덮개를 닫는 동작은 확장에서 막을 수 없습니다.

## 설치

1. Chrome에서 `chrome://extensions`를 엽니다.
2. 우측 상단 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 디렉터리를 선택합니다.

```text
/Users/gabriel.k/Documents/Workspace/floutomation
```

5. [Google Flow](https://labs.google/fx/tools/flow/)에서 프로젝트를 열고, Chrome 도구 모음의 확장 아이콘을 누릅니다.

확장을 새로 로드하기 전에 이미 열려 있던 Flow 탭은 한 번 새로고침해야 콘텐츠 스크립트가 연결될 수 있습니다. 사이드패널의 **연결 확인** 버튼으로 상태를 확인할 수 있습니다.

이 확장은 Flow의 Slate 편집기가 자동 입력을 실제 타이핑으로 처리하도록 `debugger` 권한을 사용합니다. 작업할 때 Flow 탭에만 잠깐 연결해 포커스된 입력란의 기존 문장을 지우고 텍스트를 입력한 뒤 즉시 연결을 해제합니다. DevTools가 Flow 탭에 열려 있으면 충돌하므로 닫고 실행해야 합니다.

## 사용

1. `.md`/`.txt` 파일을 선택하거나 프롬프트 텍스트를 붙여넣습니다.
2. 분석된 캐릭터 수, 장면 수, `@key` 참조 횟수를 확인합니다.
3. **분석 결과를 작업 큐에 적용**을 누릅니다.
4. Flow 프로젝트 탭이 열린 상태에서 **캐릭터부터 생성 시작**을 누릅니다. 현재 위치가 장면/미디어 화면이어도 확장이 뒤로 이동해 **캐릭터 → 신규 캐릭터** 화면을 열고 입력란·모델·만들기 버튼이 모두 준비된 뒤 시작합니다.
5. 확장이 캐릭터를 파일 키와 같은 이름으로 등록합니다. 예: `@saebyeol`의 등록 이름은 `saebyeol`입니다.
6. 모든 캐릭터가 준비되면 장면 이미지 큐가 자동으로 시작됩니다.
7. 각 캐릭터와 장면의 설정, 생성, 결과 감지, 대기 상태를 사이드패널에서 확인합니다.
8. 큐를 중단하거나 모두 완료한 뒤 **프로젝트 ZIP 다운로드**를 눌러 결과를 한 개의 ZIP 파일로 저장합니다.

### 수동 생성 모드

자동 제출 대신 각 작업 카드의 **수동 프롬프트 보내기**를 누를 수 있습니다. 확장은 Flow의 일반 이미지 설정과 캐릭터 참조 칩, 해당 이미지 프롬프트까지만 입력하고 생성 버튼이나 Enter는 누르지 않습니다. Flow에서 직접 생성한 결과를 확인한 뒤 카드의 **생성 완료 처리**를 눌러야 다음 작업을 수동으로 준비할 수 있습니다.

### 인트로·썸네일 스틸 이미지 생성

기존 장면/캐릭터 생성이 들어 있는 **같은 Flow 프로젝트**에서 사이드패널의 **인트로 이미지** 모드를 선택합니다. 위 파일 영역에는 인트로훅 `.txt`를 넣고, 아래 **썸네일 프롬프트** 영역에는 썸네일 한 장용 텍스트를 붙여 넣습니다. 둘은 함께 큐에 등록되며, 썸네일은 인트로 씬 뒤에 실행됩니다.

인트로훅 파일에서는 각 `===== 씬 N =====` 블록의 **`[A] 이미지 프롬프트`** 코드 블록만 추출합니다. `[B] 영상 프롬프트`, 대사, 폴백 지침은 이미지 생성에 포함하지 않습니다. 인트로와 썸네일 모두 현재 큐에 저장된 캐릭터를 새로 만들거나 지우지 않고 그대로 사용합니다. 따라서 먼저 장면 모드에서 캐릭터를 준비한 뒤 전환해야 하며, `@dongnae`처럼 프롬프트에 포함된 참조가 현재 프로젝트의 캐릭터 키와 일치하지 않으면 큐 적용이 비활성화됩니다.

프로젝트 ZIP 다운로드는 Flow의 카드별 다운로드 버튼을 누르지 않습니다. **모든 미디어** 카드 DOM을 한 번만 훑어 원본 `media.getMediaUrlRedirect` URL을 수집하고, Flow의 최신순 카드 배열을 오래된 순으로 뒤집습니다. 사용자가 맞춰 둔 카드 순서를 그대로 `001-1.jpeg`, `001-2.jpeg`, `002-1.jpeg`, `002-2.jpeg`에 연결하며, 프롬프트 비교나 이미지 상세 화면 재방문은 하지 않습니다. 원본을 ZIP 하나로 묶어 내려받으므로 운영체제의 파일별 다운로드 완료 알림도 한 번만 발생합니다.

원본 URL의 첫 요청은 로그인된 Flow 세션을 사용하고, 리다이렉트된 `flow-content.google` CDN은 확장의 전용 호스트 권한으로 가져옵니다. 각 원본은 30초 타임아웃과 최대 3회 재시도를 적용합니다. 실패하면 진행 표시 아래에 파일명과 원인이 계속 남으므로 토스트가 사라져도 오류를 확인할 수 있습니다. 다운로드 스캔에서 확인한 실제 장면 카드 수도 상단 **생성 이미지** 수에 동기화됩니다.

Google Flow가 CAPTCHA, 로그인 확인 또는 자동 요청 확인 페이지를 표시하면 확장은 이를 우회하지 않습니다. ZIP 수집은 첫 원본 요청에서 즉시 멈추며, Flow 탭에서 해당 확인을 직접 완료한 뒤 다시 시도해야 합니다.

```text
Flow Batch Studio/프로젝트이름-YYYYMMDD-HHMMSS/
├── 001-1.jpeg
├── 001-2.jpeg
├── 002-1.jpeg
├── 002-2.jpeg
├── daein.jpeg
├── myeong.jpeg
└── ...
```

다운로드 전에 장면 프롬프트 개수 × 2와 수집 카드 수를 함께 보여 줍니다. 카드가 부족하면 가능한 앞 번호만 저장하고 부족한 장면 번호를 결과에 표시합니다. 카드가 더 많으면 앞에서부터 필요한 수만 사용하므로, 다운로드 전 모든 미디어의 장면 카드 순서를 먼저 정리해 두어야 합니다. 캐릭터는 캐릭터 목록에서 같은 키의 원본 이미지 URL을 별도로 읽어 같은 폴더에 저장합니다.

큐 적용 시 확장이 Flow의 캐릭터 목록을 열어 같은 ASCII 이름으로 등록된 캐릭터를 자동 확인합니다. 같은 파일을 다시 적용해도 완료된 캐릭터와 장면 상태를 유지합니다. 캐릭터 카드 우측 체크박스를 사용하면 Flow에 이미 존재하는 항목을 직접 완료 처리하거나, 체크를 풀어 해당 캐릭터부터 다시 시작할 수 있습니다. 장면 카드 체크박스도 동일하게 동작하여 임의의 장면 번호부터 이어갈 수 있습니다. **Flow와 동기화** 버튼은 큐가 중단된 상태에서 현재 Flow 목록과 상태를 다시 맞춥니다.

**현재 작업 후 중단**은 이미 Flow에 전송된 생성 요청의 완료까지 확인한 다음 다음 작업을 막습니다. 전송 전이라면 즉시 대기 상태로 돌립니다. **이어서 실행**을 누르면 남은 첫 작업부터 계속합니다.

실패한 캐릭터 카드에는 **@이름 다시 생성** 버튼이 표시됩니다. 해당 캐릭터만 즉시 재시도할 수 있고, 하단의 **실패 작업 다시 실행**은 실패한 캐릭터와 장면을 원래 순서대로 모두 대기열에 복귀시킨 뒤 곧바로 실행합니다. 실패가 남아 있을 때 일반 **이어서 실행**은 숨겨져 실패 작업을 실수로 건너뛰지 않습니다.

Flow에서 생성 전 확인이 `항상`으로 되어 있으면 자동 실행을 위해 해당 에이전트 설정을 `안 함`으로 바꾸고 저장합니다. CAPTCHA, 사용자 확인, 크레딧/할당량 오류를 감지하면 큐는 자동으로 중단되며 우회하지 않습니다.

캐릭터 참조 이미지가 생성된 뒤 Flow가 이미지 선택을 요구하여 자동 등록을 확정할 수 없는 경우, 확장은 해당 캐릭터를 **검수** 상태로 멈춥니다. Flow에서 이미지 1~2장을 선택하고 화면에 표시된 ASCII 이름으로 저장한 다음 사이드패널의 **저장 완료 — 계속**을 누르면 됩니다.

캐릭터 생성 직후 Flow가 신규 캐릭터 화면에서 프로젝트 목록으로 페이지를 전환하는 것은 정상 동작으로 처리합니다. 새 페이지에서 등록된 이름과 이미지를 다시 찾아 완료 상태를 복구하며, 이 전환을 더 이상 비정상 새로고침으로 실패 처리하지 않습니다. 메뉴 클릭 뒤에는 약 1.8초, 일반 동작 뒤에는 약 1.2초의 UI 안정화 시간을 둡니다.

이미 같은 이름의 캐릭터가 프로젝트에 등록되어 있으면 **동일한 이름의 캐릭터가 이미 등록됨**을 선택해 캐릭터 생성 단계를 건너뛸 수 있습니다.

## Flow 캐릭터 문서 형식

Flow의 공식 캐릭터 절차는 시각 참조 1~2장 생성 또는 업로드, 캐릭터 이름 지정, 저장 순서입니다. 자세한 제품 동작은 [Google Flow 캐릭터 관리 도움말](https://support.google.com/labs/answer/16935308?hl=ko)을 참고하세요.

다음 구조는 일반 번호 목록보다 먼저 인식됩니다.

```text
=== saebyeol (새별, 인물 설명 / 챕터 2~50) ===
=== saebyeol UPLOAD ===
Single figure portrait ...

[대본 1~50]
1. 첫 번째 대본 문장

===프롬프트===
[영어 프롬프트 1~50]
1. @saebyeol ... @nurse ...
```

분석 시 다음을 검증합니다.

- 캐릭터 키와 `UPLOAD` 프롬프트의 대응
- 대본 번호와 이미지 프롬프트 번호의 대응
- 장면 번호가 1부터 연속되는지 여부
- 모든 `@key`가 캐릭터 정의에 존재하는지 여부
- 캐릭터별 장면 참조 횟수

장면 작업은 Flow 에이전트를 사용하지 않습니다. 작업마다 왼쪽 **모든 미디어**를 먼저 클릭하고, 열려 있는 에이전트 대화 패널을 닫은 뒤 하단 **에이전트** 토글을 OFF로 맞춥니다. 일반 생성 설정에서 **이미지 · 16:9 · x2 · 사이드패널에서 선택한 모델**을 검증한 다음 프롬프트를 전송합니다. 모델 한도가 소진되면 사이드패널에서 다른 모델로 바꾸고 **실패 작업 다시 실행**을 눌러 같은 장면부터 이어갈 수 있습니다. 각 `@key`는 실제 `@` 키 입력으로 Flow 애셋 창을 열고, **애셋 검색 → 정확히 일치하는 캐릭터 결과 확인 → 프롬프트에 추가** 과정을 거쳐 참조 칩으로 연결합니다. 참조 칩은 버튼 내부 이미지의 접근성 이름과 칩 개수 증가로 판정합니다. 이후 `@key`를 제외한 장면 문장 전체가 편집기에 들어갔는지 다시 검증하며, 캐릭터가 없거나 본문이 누락되면 생성 버튼을 누르기 전에 해당 장면에서 중단됩니다.

애셋 참조창에서는 검색 전에 반드시 왼쪽 **캐릭터** 필터를 선택합니다. **모두** 검색 결과에 같은 이름이 포함된 일반 이미지가 있어도 선택하지 않으며, 캐릭터 필터 안에서 파일 키와 정확히 일치하는 결과만 프롬프트 참조 칩으로 추가합니다.

Flow가 작업 도중 페이지를 다시 로드해도 장면을 즉시 실패 처리하지 않습니다. 제출 전 기준 미디어와 제출 시각을 백그라운드 저장소에 확실히 기록한 뒤 만들기 버튼을 누르며, 새 페이지에서는 **진행 카드 또는 기준 이후 새 미디어가 있으면 기존 생성을 계속 추적**하고, 생성 흔적이 없을 때만 동일 장면의 설정부터 자동으로 재개합니다. 이미 선택된 **모든 미디어** 메뉴는 다시 클릭하지 않아 불필요한 화면 전환도 방지합니다.

Flow의 생성 카드는 ARIA progressbar가 아니라 일반 `div` 안에 `30%`, `40%` 같은 텍스트로 진행률을 표시합니다. 확장은 CSS 해시 클래스에 의존하지 않고 **image 아이콘 · 정확한 퍼센트 텍스트 · 현재 프롬프트 본문**을 함께 확인해 생성 카드를 식별합니다. 두 장의 진행률은 `이미지 1 40% · 이미지 2 40%` 형태로 작업 단계와 개별 배지에 표시됩니다.

캐릭터 참조 연결, 일시적인 Flow DOM 변경, 화면 전환, 상태 감시 오류처럼 사용자 조치가 필요하지 않은 장면 오류는 큐를 멈추지 않습니다. 같은 장면을 15초, 30초, 이후 최대 60초 간격으로 횟수 제한 없이 자동 재시도하며, **현재 작업 후 중단/대기열 중단**을 누르면 예약된 재시도도 취소됩니다. 이미 생성 요청이 제출된 작업은 프롬프트를 다시 보내지 않고 기존 생성 결과 추적부터 재개합니다. CAPTCHA, 로그인, 계정 한도·크레딧, 디버거 충돌처럼 사용자 조치가 필요한 오류만 일시 중단합니다.

## 지원하는 프롬프트 문서 형식

분석기는 다음 우선순위로 작업을 나눕니다.

1. Flow 캐릭터 문서
2. `##`~`####` Markdown 제목별 섹션
3. `Prompt 1:`, `프롬프트 2:` 라벨
4. 번호 또는 불릿 목록
5. `---`, `===`, `***` 구분선
6. 빈 줄로 나뉜 블록
7. 줄 단위 프롬프트

예시:

```md
## 빗속의 골목
네온사인이 반사되는 비 오는 밤의 골목, 시네마틱 와이드 숏

## 사막의 도시
정오의 태양 아래 반투명 유리로 된 미래 도시, 대칭 구도
```

## 동작 구조

- `sidepanel.js`: 캐릭터/장면 분석, 매핑 현황, 큐/진행 UI, 검수·중단·이어하기, 프로젝트 ZIP 다운로드 제어
- `background.js`: 캐릭터 우선 영속 상태 머신, Flow 탭 연결, 실제 키 입력 전달, 60초 알람 스케줄링, 이미지 다운로드 실행
- `content.js`: 캐릭터 메뉴와 모든 미디어 일반 생성 화면 강제 진입, 에이전트 OFF, 캐릭터 생성·등록, `@key` 애셋 검색·참조 칩 연결, Flow 설정 검증, 생성 완료/오류 감지, 원본 URL 수집
- `lib/prompt-parser.js`: Flow 전용 문서 및 Markdown/텍스트 프롬프트 분석
- `lib/queue-state.js`: 캐릭터 → 장면 작업 순서와 강제 최소 간격
- `lib/download-manifest.js`: 모든 미디어 카드 순서 기반 `001-1.jpeg` 형식의 다운로드 목록 생성
- `lib/zip-archive.js`: 결과 이미지를 한 개의 ZIP 파일로 묶는 표준 ZIP 작성기

고정 `setTimeout`으로 60초를 버티지 않고 `chrome.alarms`를 사용하므로 Manifest V3 서비스 워커가 정지되어도 다음 작업 시각이 유지됩니다.

## 검증

```bash
npm run check
```

이 명령은 확장 스크립트의 문법 검사와 Node 내장 테스트 러너 기반 단위 테스트를 실행합니다.

## 제한 사항

- Google Flow의 공식 배치 API가 아니라 현재 웹 UI의 접근 가능한 라벨과 DOM을 사용합니다. Flow UI가 크게 바뀌면 연결 진단 또는 선택자 보정이 필요할 수 있습니다.
- Google 공식 도움말 기준으로 캐릭터는 최소 한 장의 시각 참조가 필요하며, 생성 후 이름을 저장해야 프롬프트에서 사용할 수 있습니다. 확장은 이 순서를 따릅니다.
- 60초 이상 간격은 요청 빈도를 낮추지만 서비스의 자동화 정책 준수를 보장하거나 탐지를 우회하지 않습니다. 계정 정책과 사용 한도는 사용자가 확인해야 합니다.
- 확장은 이미 로그인된 Flow 탭에서만 동작하며 로그인, CAPTCHA, 결제 또는 계정 확인을 대신 처리하지 않습니다.
- 라이브 E2E 생성은 실제 Flow 크레딧을 사용하므로 자동 테스트에 포함하지 않았습니다.
