# Flow Batch Studio <small>v0.9.16</small>

Google Flow에서 캐릭터·장면·인트로·썸네일 이미지 작업을 순서대로 실행하고, 결과를 프로젝트별 ZIP 파일로 저장하는 Chrome 확장 프로그램입니다.

## 주요 기능 안내

- `Flow_Prompts` 파일을 분석해 캐릭터·장면 작업을 자동으로 나눕니다.
- 캐릭터를 먼저 Flow에 생성·등록한 뒤 장면 이미지를 순서대로 생성합니다.
- 장면 프롬프트의 캐릭터 참조 이미지를 Flow 애셋과 연결합니다.
- 인트로훅의 `[A] 이미지 프롬프트`와 썸네일 프롬프트를 추가 생성합니다.
- 이전 Flow 프로젝트에서 인트로 파일을 올리면 등록된 캐릭터를 자동으로 다시 읽어 연결합니다.
- 모델, 화면 비율, 이미지 장수, 고정·랜덤 대기시간을 설정합니다.
- 대기열 중단, 이어서 실행, 실패 작업 재실행, 수동 생성이 가능합니다.
- 자동 전송 뒤 Flow의 실제 생성 시작 신호를 확인하고, 신호가 없을 때만 키보드 전송으로 한 번 재시도합니다.
- 프롬프트 복사와 생성된 이미지의 Flow 상세 화면 열기를 지원합니다.
- 이미지 asset ID를 추적해 장면·인트로·썸네일 번호를 유지합니다.
- 장면 카드에서 생성 결과를 `#1`, `#2`처럼 확인하고, 잘못 연결된 결과는 `×`로 연결만 해제할 수 있습니다.
- 장면 결과 썸네일을 다른 장면 카드로 드래그해 이미지 연결을 바로 이동할 수 있습니다.
- Flow에서 삭제되어 현재 미디어 목록에 없는 오래된 연결도 이미지 매핑 하단에서 확인·해제할 수 있습니다.
- 이미지 매핑에서 시작 이미지와 시작 장면을 지정해 이후 구간을 작업 번호 순서대로 다시 채울 수 있습니다.
- 프로젝트 ID별로 결과 asset ID와 수동 매핑을 로컬에 보관해, 이전 Flow 프로젝트로 돌아와도 같은 장면 번호에 다시 연결합니다.
- 프로젝트 제목으로 ZIP 파일명을 만들고 `Scene_Images` 폴더로 정리합니다.
- 생성 이미지·캐릭터·인트로·썸네일을 한 번에 다운로드합니다.

## 빠른 가이드

### 1. 이미지 프롬프트 파일 넣기

사이드패널의 `01 이미지생성 작업준비`에서 **장면 생성**을 선택하고 `Flow_Prompts` `.md`/`.txt` 파일을 드롭합니다.

### 2. 장면 큐 적용

분석 결과가 예상한 캐릭터 수와 장면 수인지 확인한 뒤 **분석 결과를 작업 큐에 적용**을 누릅니다.

### 3. 캐릭터와 장면 생성

기본 설정 그대로 **생성 시작**을 누릅니다.

신규 Flow 프로젝트에는 등록된 캐릭터가 없으므로 캐릭터를 먼저 생성·등록하고, 이어서 장면 이미지를 순서대로 생성합니다.

### 4. 인트로훅과 썸네일 추가 (Grok으로 만드는 경우엔 이 과정 패스)

장면 생성이 끝나면 **인트로 이미지** 탭에서:

1. 인트로훅 `.txt`/`.md` 파일을 드롭합니다.
2. 썸네일 프롬프트를 붙여 넣습니다.
3. **인트로·썸네일 작업 큐에 적용**을 누릅니다.
4. **생성 시작**을 누릅니다.

인트로 이미지가 순서대로 생성된 뒤 썸네일이 생성됩니다. 같은 Flow 프로젝트의 캐릭터를 자동으로 재사용합니다.

이전에 끝낸 프로젝트로 돌아온 경우에는 Flow 프로젝트를 열고 패널의 연결 상태를 확인합니다. 프로젝트 기록이 있으면 캐릭터와 장면 매핑을 자동 복원하고, 기록이 없는 구버전 프로젝트도 Flow에 등록된 캐릭터를 자동 발견해 인트로·썸네일에서 재사용할 수 있습니다. 구버전 프로젝트에 장면 매핑 기록이 없으면 기존 장면 이미지는 자동으로 장면을 판별할 수 없으므로 이미지 매핑에서 직접 지정해야 합니다. 동기화에 실패하면 인트로 파일을 올릴 때도 캐릭터 검색을 다시 시도합니다.

### 5. 전체 다운로드

모든 작업이 끝나면 QUEUE STATUS의 **전체 다운로드**를 누릅니다.

```text
Flow_Prompts 드롭
  → 장면 큐 적용
  → 생성 시작
  → 캐릭터 생성
  → 장면 이미지 생성
  → 인트로훅 + 썸네일 큐 적용
  → 추가 이미지 생성
  → 전체 다운로드
```

이 요약 흐름에서 벗어나는 상황은 [상세 가이드](#상세-가이드)의 해당 항목만 확인하면 됩니다.

## 상세 가이드

### 1. 사용 전 꼭 확인할 사항

#### 필요한 환경

- Google Chrome 116 이상
- 로그인되어 있고 이미지 생성을 사용할 수 있는 Google Flow 계정
- 작업할 Flow 프로젝트 탭
- 이 확장 프로그램이 해당 Flow 탭을 찾을 수 있도록 열려 있는 프로젝트 화면

확장은 Google Flow의 공식 배치 API를 사용하는 것이 아니라 Flow 웹 화면의 버튼, 입력창, 접근성 라벨, 미디어 카드 DOM을 제어합니다. 따라서 Flow 화면이 크게 바뀌면 연결 확인이나 작업이 실패할 수 있습니다.

#### 작업 전에 확인할 것

1. Flow에서 올바른 프로젝트를 엽니다.
2. Flow 탭에서 DevTools를 닫습니다.
3. Flow에서 CAPTCHA, 로그인 확인, 계정 확인 화면이 떠 있지 않은지 확인합니다.
4. 생성할 프롬프트 파일의 캐릭터 키와 Flow에 등록된 캐릭터 이름을 확인합니다.
5. 자동 실행 중에는 Flow 탭을 닫지 않습니다.

Chrome 창을 최소화해도 큐 상태 저장과 다음 작업 예약은 계속 작동하도록 설계되어 있습니다. 다만 실제 생성 완료 감시는 Flow 페이지의 DOM을 주기적으로 읽으므로 백그라운드 탭 throttling, Energy Saver, 메모리 절약에 의해 지연될 수 있습니다. 장시간 자동 실행은 Flow 탭과 Chrome을 표시 상태로 유지하는 것이 가장 안전합니다.

### 2. 설치와 첫 실행

#### 확장 프로그램 설치

1. 프로젝트 폴더를 준비합니다.
2. Chrome 주소창에 `chrome://extensions`를 입력합니다.
3. 우측 상단의 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
5. 이 저장소의 최상위 폴더를 선택합니다.
6. [Google Flow](https://labs.google/fx/tools/flow/) 또는 `https://flow.google.com/project/{프로젝트ID}`에서 작업할 프로젝트를 엽니다.
7. Chrome 도구 모음에서 Flow Batch Studio 아이콘을 눌러 사이드패널을 엽니다.

코드가 변경된 뒤에는 `chrome://extensions`에서 확장 프로그램의 새로고침 아이콘을 눌러야 새 버전이 적용됩니다. 이미 열려 있던 Flow 탭에서 연결되지 않으면 해당 탭도 한 번 새로고침한 뒤 사이드패널의 **연결 확인**을 누릅니다.

#### 첫 연결

사이드패널 상단에서 다음 순서로 진행합니다.

1. **Flow 열기**: Flow 프로젝트 화면을 엽니다.
2. **연결 확인**: 현재 탭이 Flow 프로젝트인지, 자동화에 필요한 화면 요소가 있는지 확인합니다.
3. 상태가 **Flow 연결됨**으로 바뀌는지 확인합니다.

연결 상태는 사이드패널이 열려 있는 동안 약 2초마다 자동으로 새로 확인됩니다. 연결이 끊긴 상태라면 상태 버튼을 다시 누르거나 **Flow 열기**로 프로젝트 화면을 엽니다.

### 3. 기본 실행 절차

#### 장면과 캐릭터를 함께 생성하는 기본 순서

1. Flow 프로젝트를 열고 **연결 확인**을 누릅니다.
2. `01 이미지생성 작업준비`에서 **장면 생성**을 선택합니다.
3. `Flow_Prompts` `.md`/`.txt` 파일을 선택하거나 프롬프트를 붙여 넣습니다.
4. 분석 결과에서 작업 수, 캐릭터 수, 장면 수, 경고를 확인합니다.
5. `02 생성 규칙`에서 모델, 비율, 장수, 작업 사이 대기시간을 지정합니다.
6. **분석 결과를 작업 큐에 적용**을 누릅니다.
7. Flow에 이미 등록된 캐릭터가 있으면 캐릭터 카드의 체크박스를 켜거나 **Flow와 동기화**를 누릅니다.
8. **생성 시작**을 누릅니다.
9. 캐릭터 작업이 끝나면 장면 작업이 자동으로 이어집니다.
10. 모든 작업이 끝나거나 필요한 시점에 **전체 다운로드**를 누릅니다.

#### 이미 캐릭터가 등록된 프로젝트에서 장면만 생성

1. 같은 Flow 프로젝트에서 **연결 확인**을 합니다.
2. 장면 프롬프트를 분석합니다.
3. 작업 큐를 적용합니다.
4. `캐릭터 준비`에서 Flow에 이미 등록된 캐릭터의 체크박스를 켭니다.
5. **생성 시작**을 누르면 해당 캐릭터는 건너뛰고 장면부터 실행됩니다.

문서의 `@characterKey`와 Flow에 등록된 캐릭터 이름이 정확히 일치해야 참조 이미지가 연결됩니다.

#### 시작 전에 반드시 볼 항목

- 분석 결과의 작업 수가 예상과 같은가?
- 장면 번호가 빠지거나 중복되지 않았는가?
- `@key`가 정의되지 않았다는 경고가 없는가?
- 캐릭터 카드에서 이미 등록된 캐릭터를 건너뛸 것인가?
- 기본 이미지 수 2장이 필요한가, 1~4장 중 다른 값을 사용할 것인가?
- Flow 계정의 일일 생성 한도와 크레딧이 남아 있는가?

### 4. 화면과 버튼 안내

#### 상단 연결 영역

- **Flow 열기**: Google Flow 화면을 새로 엽니다.
- **연결 확인**: Flow 탭과 확장 프로그램의 연결을 즉시 확인합니다.
- **Flow 연결됨**: 현재 프로젝트 화면을 찾았고 자동화 진단이 통과한 상태입니다.
- **연결 안 됨**: 프로젝트 탭이 없거나 필요한 Flow 화면 요소를 찾지 못한 상태입니다.

#### QUEUE STATUS

상태 카드에는 다음 정보가 표시됩니다.

1. 완료 작업
2. 남은 작업
3. 캐릭터
4. 생성 이미지

캐릭터 작업도 전체 작업 수에 포함됩니다. 예를 들어 캐릭터 5개와 장면 40개라면 전체 작업은 45개이며, 캐릭터 5개가 이미 완료된 경우 완료·남은 작업 수에서 그 상태가 반영됩니다.

버튼의 의미:

- **전체 다운로드**: Flow의 현재 프로젝트 미디어를 스캔해 ZIP으로 저장합니다. 실행 중에는 사용할 수 없습니다.
- **새로시작**: 현재 큐, 장면·인트로·썸네일 입력 초안, 파일 선택 상태를 초기화합니다. Flow에 이미 생성된 이미지를 삭제하지는 않습니다.
- **생성 시작**: 적용된 큐를 처음부터 실행합니다.
- **대기열 중단**: 현재 큐를 즉시 일시정지하고 active 작업을 대기 상태로 돌립니다.
- **이어서 실행**: 일시정지된 큐에서 남은 첫 작업부터 계속합니다.
- **실패 작업 다시 실행**: 최종 실패한 캐릭터와 이미지 작업을 다시 대기열에 넣고 재실행합니다.

#### 01 이미지생성 작업준비

##### 장면 생성 탭

- Flow 전용 캐릭터·장면 문서
- 일반 Markdown
- 번호 목록
- 프롬프트 라벨
- 일반 텍스트

를 분석합니다.

##### 인트로 이미지 탭

- 인트로훅 `.txt`/`.md` 파일
- 썸네일 프롬프트 한 건

을 함께 준비합니다. 인트로 모드에서는 기존 캐릭터를 사용하며 캐릭터를 새로 등록하지 않습니다.

##### 파일 입력 영역

허용 확장자는 `.md`, `.txt`입니다. 파일을 선택하거나 드롭 영역에 놓을 수 있고, 아래 텍스트 영역에 직접 붙여 넣을 수도 있습니다.

분석 결과는 목록 대신 다음과 같이 요약됩니다.

- 장면 모드: `N개 작업 · 캐릭터 N명 · 장면 N장`
- 인트로 모드: `N개 작업 · 기존 캐릭터 N명 · 인트로 N장 · 썸네일 N장`

인식 실패 원인은 분석 영역 아래 경고로 표시됩니다. 경고가 있는데도 큐 적용이 가능하다면 줄 단위나 단일 프롬프트로 해석되었을 가능성이 있으므로 작업 수를 반드시 확인합니다.

#### 02 생성 규칙

- 생성 모델
- 화면 비율
- 프롬프트당 이미지 장수
- 작업 사이 고정 대기시간
- 랜덤시간 사용 여부

를 설정합니다. 자세한 값은 [생성 규칙 설정](#7-생성-규칙-설정)을 참고하세요.

#### 03 캐릭터 준비

장면 큐가 적용되고 캐릭터가 포함되어 있을 때 표시됩니다.

- **Flow와 동기화**: 현재 Flow에 등록된 캐릭터와 확장에 저장된 같은 프로젝트의 캐릭터 정보를 대조합니다.
- 체크박스 켜기: Flow에 이미 등록된 캐릭터로 처리해 생성 단계를 건너뜁니다.
- 체크박스 끄기: 해당 캐릭터부터 다시 생성 대상으로 돌립니다.
- **Flow에서 @키 저장 완료 — 계속**: Flow에서 이미지 선택과 캐릭터 저장을 직접 끝낸 뒤 검수 상태를 완료로 바꿉니다.
- **@키 처음부터 다시 생성**: 실패한 캐릭터를 처음 단계부터 다시 실행합니다.

#### 04 이미지 작업 목록

각 작업 카드에는 프롬프트와 현재 단계가 표시됩니다.

- **복사**: 해당 장면·인트로·썸네일 프롬프트를 클립보드로 복사합니다.
- **보러가기**: 저장된 asset ID 또는 상세 URL이 있으면 Flow의 이미지 상세 화면을 새 탭으로 엽니다.
- **수동 프롬프트 보내기**: 프롬프트와 설정만 Flow에 준비하고 자동 생성 버튼은 누르지 않습니다.
- **생성 완료 처리**: Flow에서 직접 생성한 뒤 해당 작업을 완료로 표시합니다.
- 카드 우측 체크박스: 이미 끝난 작업을 건너뛰는 시작 지점을 지정합니다.
- **실패 재시도**: 특정 실패 작업만 다시 시도합니다.

### 5. 장면·캐릭터 이미지 생성

#### 캐릭터 생성 순서

자동 실행은 다음 순서로 동작합니다.

1. 캐릭터 작업을 찾습니다.
2. Flow의 캐릭터 생성 화면으로 이동합니다.
3. 캐릭터 설명과 참조 이미지를 입력합니다.
4. 선택한 모델로 생성합니다.
5. 참조 이미지 선택이 필요한 경우 `검수` 상태로 멈춥니다.
6. 캐릭터 이름을 파일 키와 같은 ASCII 이름으로 저장합니다.
7. Flow 프로젝트 화면으로 돌아온 뒤 등록 결과를 다시 확인합니다.
8. 모든 캐릭터가 완료되면 장면 작업으로 넘어갑니다.

캐릭터 이미지 선택이나 저장을 직접 해야 하는 경우:

1. Flow에서 참조 이미지 1~2장을 선택합니다.
2. 문서의 키와 같은 이름으로 저장합니다. 예: `@saebyeol` → `saebyeol`
3. 사이드패널의 **Flow에서 @saebyeol 저장 완료 — 계속**을 누릅니다.

#### 장면 생성 순서

각 장면마다 다음을 확인합니다.

1. Flow의 **모든 미디어** 화면으로 이동합니다.
2. 에이전트 모드를 끕니다.
3. 모델, 화면 비율, 이미지 장수를 확인합니다.
4. 프롬프트의 `@key`를 Flow 캐릭터 애셋으로 연결합니다.
5. 캐릭터 참조 칩이 실제로 추가되었는지 확인합니다.
6. 프롬프트 본문 누락 여부를 확인합니다.
7. 프롬프트를 전송하고 생성합니다.
8. 진행률, 완료 이미지, 오류 카드를 감시합니다.
9. 요청한 이미지 수가 모두 확인된 경우에만 작업을 완료 처리합니다.

캐릭터 참조를 찾을 때는 Flow 애셋 창의 **캐릭터** 필터에서 문서 키와 정확히 일치하는 결과를 선택합니다. 같은 이름의 일반 이미지가 있어도 캐릭터 필터에서 일치하지 않으면 사용하지 않습니다.

### 6. 인트로·썸네일 이미지 생성

인트로·썸네일은 장면 작업과 같은 Flow 프로젝트에서 기존 캐릭터를 재사용합니다. 먼저 해당 프로젝트의 캐릭터가 Flow에 등록되어 있어야 합니다.

#### 입력 순서

1. `01 이미지생성 작업준비`에서 **인트로 이미지**를 선택합니다.
2. 인트로훅 `.txt` 또는 `.md` 파일을 선택합니다.
3. 썸네일 프롬프트 영역에 한 건의 프롬프트를 입력합니다.
4. 인트로 씬 수와 썸네일 수를 확인합니다.
5. **인트로·썸네일 작업 큐에 적용**을 누릅니다.
6. 인트로 작업이 순서대로 실행된 뒤 썸네일 작업이 실행됩니다.

#### 인트로훅에서 읽는 부분

각 씬 블록에서 `[A] 이미지 프롬프트`만 이미지 생성 작업으로 사용합니다.

- `[B] 영상 프롬프트`: 사용하지 않음
- 대사와 설명: 사용하지 않음
- 모더레이션 메모와 괄호 설명: 씬 제목 뒤에 붙어 있어도 인식 가능

다음 형식은 모두 인식됩니다.

```text
===== 씬 6 =====
===== 씬 6 ===== ※ 모더레이션 대응 수정본
===== 씬 5 ===== (클라이맥스)
===== 씬 4 ===== 임시 수정본 #2
```

조건은 앞부분이 `===== 씬 숫자 =====`로 시작하는 것입니다. 닫는 등호 뒤에는 어떤 문자가 붙어도 됩니다.

예시:

```text
===== 씬 1 ===== (오프닝)
[A] 이미지 프롬프트
비 오는 새벽의 골목, 가로등 아래 서 있는 @saebyeol
[B] 영상 프롬프트
카메라가 천천히 앞으로 이동한다.
```

`@key`가 현재 Flow 프로젝트에 없으면 큐 적용이 막힙니다. 먼저 장면 모드에서 캐릭터를 준비하거나 **Flow와 동기화**를 실행하세요.

### 7. 생성 규칙 설정

#### 모델

지원 모델:

- `Nano Banana Pro`
- `Nano Banana 2` (기본값)
- `Nano Banana 2 Lite`

일일 한도나 모델별 오류가 발생하면 오류 메시지에 표시된 모델을 확인하고, 다른 모델로 바꾼 뒤 **실패 작업 다시 실행**을 누릅니다.

#### 화면 비율

- `16:9` (기본값)
- `4:3`
- `1:1`
- `3:4`
- `9:16`

확장은 작업을 시작할 때마다 Flow의 현재 일반 이미지 설정을 선택한 값과 비교합니다. 화면에 설정 메뉴가 열려 있거나 다른 작업이 진행 중이면 설정 검증이 실패할 수 있습니다.

#### 이미지 장수

프롬프트당 `1장`부터 `4장`까지 선택할 수 있습니다. 기본값은 `2장`입니다.

요청한 장수만큼 결과 URL이 확인되어야 생성 완료로 처리됩니다. 한 장이라도 부족하면 자동 재시도 또는 실패 처리가 발생할 수 있습니다.

#### 작업 사이 대기

- 고정 모드: `60초`~`120초`
- 랜덤시간: 매 작업마다 `60초`~`90초` 사이에서 새로 선택

랜덤시간을 켜면 고정 대기 슬라이더가 비활성화됩니다. 대기시간은 작업 요청 사이의 간격이며, Flow 생성 자체의 완료 시간은 별도입니다.

### 8. 작업 중단·재개·재시도·수동 생성

#### 대기열 중단

**대기열 중단**은 현재 큐를 즉시 일시정지합니다.

- active 작업 ID를 해제합니다.
- 현재 작업은 대기 상태로 돌립니다.
- 예약된 다음 작업과 자동 재시도를 취소합니다.
- Flow에 이미 전송된 생성 요청을 Flow 화면에서 취소하는 것은 아닙니다.

따라서 중단 직후 Flow에서 이미지가 계속 생성될 수 있습니다. 다시 실행하기 전에 Flow의 결과와 사이드패널 상태를 확인해 중복 생성을 피하세요.

#### 이어서 실행

일시정지된 큐의 남은 작업을 이어서 실행합니다. 실패 작업이 남아 있으면 일반 **이어서 실행** 대신 먼저 **실패 작업 다시 실행**을 사용해야 합니다.

#### 자동 재시도

사용자 확인이 필요하지 않은 장면 오류는 한 번 자동으로 재시도합니다.

- 첫 자동 재시도: 약 15초 후
- 자동 재시도 최대 횟수: 1회
- 두 번째 실패: `실패 · 다음 작업으로 진행`
- 이후 작업: 남아 있으면 대기시간 후 계속

자동 재시도 후에도 실패한 작업은 프롬프트를 점검하거나 모델을 변경한 뒤 **실패 재시도**를 사용합니다.

#### 자동으로 멈추는 오류

다음 오류는 자동으로 우회하지 않고 사용자 조치를 요구합니다.

- CAPTCHA 또는 사람 확인
- 로그인 만료
- 계정 확인
- 크레딧 부족
- 일일 한도·quota 초과
- DevTools 또는 다른 debugger 충돌

화면의 오류를 직접 해결한 뒤 **실패 작업 다시 실행**을 누릅니다.

#### 수동 프롬프트 보내기

자동 생성이 어려운 작업은 카드의 **수동 프롬프트 보내기**를 사용합니다.

1. 작업 카드에서 **수동 프롬프트 보내기**를 누릅니다.
2. 확장이 Flow에 모델·비율·장수·캐릭터 참조·프롬프트만 준비합니다.
3. 생성 버튼은 확장이 누르지 않습니다.
4. Flow에서 내용을 직접 확인하고 생성합니다.
5. 결과를 확인한 뒤 카드에서 **생성 완료 처리**를 누릅니다.
6. 남은 작업은 수동으로 처리하거나 **이어서 실행**으로 자동 실행을 재개합니다.

### 9. 입력 파일 형식과 분석 결과

#### 파일 확장자

파일 선택 영역은 다음 형식을 받습니다.

- `.md`
- `.txt`

확장자는 맞지만 내부 구조가 불분명하면 parser가 줄 단위 또는 전체 한 건으로 해석할 수 있습니다. 적용 전에 작업 수를 확인하세요.

#### Flow 전용 문서

Flow 캐릭터 문서는 다음 요소를 사용합니다.

```text
=== saebyeol (새별, 인물 설명 / 챕터 2~50) ===
=== saebyeol UPLOAD ===
Single figure portrait of a young woman ...

[대본 1~50]
1. 첫 번째 장면의 대본
2. 두 번째 장면의 대본

===프롬프트===
[영어 프롬프트 1~50]
1. @saebyeol ... @nurse ...
2. @saebyeol ...
```

검사 항목:

- 캐릭터 헤더와 `UPLOAD` 블록 연결
- 장면 번호 순서
- 대본과 이미지 프롬프트 번호 대응
- 모든 `@key`가 캐릭터 정의에 존재하는지
- 캐릭터별 참조 횟수

캐릭터 키는 영문자로 시작하고 영문자·숫자·밑줄·하이픈으로 구성해야 합니다. 예: `@saebyeol`, `@nurse_01`.

#### 일반 Markdown과 텍스트

다음 우선순위로 여러 작업을 나눕니다.

1. Flow 전용 캐릭터 문서
2. `##`~`####` Markdown 제목 섹션
3. `Prompt 1:`, `Image Prompt 2:`, `프롬프트 1:` 라벨
4. 번호 목록 또는 불릿 목록
5. `---`, `===`, `***` 구분선
6. 빈 줄로 나뉜 블록
7. 줄 단위
8. 구분할 수 없으면 전체를 1개 작업

권장 예시:

```md
## 빗속의 골목
비 오는 밤, 네온사인이 젖은 바닥에 반사되는 시네마틱 와이드 숏

## 사막의 도시
정오의 태양 아래 반투명 유리로 된 미래 도시, 대칭 구도
```

#### 분석 경고 해석

- `프롬프트를 입력하거나 파일을 선택하세요.`: 입력이 없습니다.
- `Flow_Prompts 형식...`: Flow 전용 marker 일부가 있으나 필수 구조가 완성되지 않았습니다.
- `정의되지 않은 캐릭터 참조`: 문서에 `@key`가 있지만 캐릭터 정의가 없습니다.
- `장면 번호가 1부터 연속적이지 않습니다.`: 번호가 빠졌거나 중복되었을 수 있습니다.
- `일부 이미지 프롬프트에 대응하는 대본 문장이 없습니다.`: 대본과 이미지 번호를 맞추세요.
- `명시적인 구분자를 찾지 못해 각 줄을...`: 줄마다 작업으로 해석되었습니다.
- `전체 내용을 1개 작업으로 인식했습니다.`: 빈 줄, 제목, 번호 목록 등으로 장면을 나누세요.
- 인트로의 `[A] 이미지 프롬프트` 또는 `===== 씬 N =====`가 없다는 경고: 인트로훅 구조가 맞지 않습니다.
- 현재 프로젝트에 준비되지 않은 캐릭터 참조: **Flow와 동기화** 후 문서 키를 수정하세요.

경고가 있다고 항상 큐 적용이 막히는 것은 아닙니다. 다만 `@key` 누락, 인트로 캐릭터 미준비, 빈 분석 결과는 큐 적용이 차단됩니다.

### 10. 예외 및 문제 대응

#### `연결 안 됨`이 계속 표시됨

1. **Flow 열기**를 누릅니다.
2. 올바른 프로젝트 URL인지 확인합니다.
3. Flow 탭을 새로고침합니다.
4. DevTools를 닫습니다.
5. 사이드패널에서 **연결 확인**을 누릅니다.
6. 다른 Flow 프로젝트 탭이 여러 개라면 작업할 프로젝트 탭을 최근에 활성화합니다.

Flow 프로젝트가 아닌 대시보드나 캐릭터 라이브러리 화면만 열려 있으면 프로젝트 ID를 찾지 못할 수 있습니다.

#### 다른 프로젝트의 캐릭터가 연결됨

프로젝트 ID가 다른 Flow 프로젝트의 캐릭터 이력은 인트로·썸네일 작업에 사용할 수 없습니다.

1. 작업할 프로젝트를 엽니다.
2. **Flow와 동기화**를 누릅니다.
3. 캐릭터 등록 상태를 다시 확인합니다.
4. 인트로·썸네일 분석을 다시 실행합니다.

#### `@key`가 없거나 이름이 다름

문서의 `@saebyeol`과 Flow 캐릭터 등록 이름 `saebyeol`이 정확히 일치해야 합니다. 표시용 한글 이름이나 비슷한 이름은 자동으로 같은 캐릭터로 취급하지 않습니다.

#### 캐릭터가 `검수` 상태에서 멈춤

Flow에서 참조 이미지를 선택하고 캐릭터를 저장하지 않은 상태입니다.

1. Flow에서 이미지 1~2장을 선택합니다.
2. 문서의 ASCII 키와 같은 이름으로 저장합니다.
3. 사이드패널 카드의 **Flow에서 @키 저장 완료 — 계속**을 누릅니다.

#### 프롬프트는 입력됐는데 전송 버튼을 누르지 못한 것처럼 멈춤

캐릭터 생성은 입력창 주변에서 `arrow_forward` 아이콘과 `만들기` 라벨을 동시에 가진 버튼을 정확히 찾아 `button.click()`으로 직접 실행합니다. 8초 동안 시작 신호가 없을 때만 같은 버튼에 실제 좌표 클릭을 한 번 더 시도합니다. 일반 장면 생성은 기존처럼 좌표 클릭 후 키보드 Enter 재시도를 사용합니다.

캐릭터 이미지가 만들어지면서 주소가 `/character/{asset-id}` 상세 화면으로 바뀌고 `캐릭터 이름` 입력란과 `완료` 버튼이 나타나면 생성 요청이 성공한 것으로 즉시 인정합니다. 이 화면에서 자동 실행이 중단됐더라도 **실패 작업 다시 실행**을 누르면 새 이미지를 다시 만들지 않고 현재 상세 화면의 이름 저장부터 이어서 처리합니다.

그래도 시작되지 않으면 24초 안에 작업을 실패로 멈추고, 캐릭터 카드에 `최근 전송 진단`으로 버튼의 활성 상태·컨트롤 유형·크기·클릭 중심의 실제 DOM 대상·접근성 라벨을 보여 줍니다. 해당 문구에 `활성`과 `button`이 함께 남아 있으면 프롬프트 길이 문제가 아니라 Flow가 자동 전송을 접수하지 않은 경우입니다. Flow 탭의 화면 오류나 사용자 확인 메시지를 먼저 확인한 뒤 **실패 작업 다시 실행**을 누르세요.

#### 이미지가 한 장만 생성되거나 결과 URL이 부족함

2장 생성 요청에서 결과가 1장만 확인된 완료 장면에는 **한장더 만들어 채우기** 버튼이 표시됩니다. 버튼을 누르면 같은 프롬프트와 캐릭터 바인딩으로 부족한 2장을 다시 생성하고, 새 asset ID만 기존 1장 뒤에 연결해 총 3장으로 만듭니다. 보충 요청에서도 1장만 추가되면 목표 3장을 기억하므로 버튼이 유지되며, 다음 실행은 남은 1장만 요청합니다. 보충 실패나 사용자 중단 시 기존 이미지는 삭제하지 않습니다.

요청 장수가 2장 이상이면 모든 이미지 URL이 확인되어야 작업이 완료됩니다. Flow에서 생성 중인지, 일부 결과만 보이는지 확인하세요. 자동 재시도 후에도 부족하면 작업이 실패로 남습니다.

#### 생성 중 Flow 페이지가 새로고침됨

확장은 제출 전 기준 미디어와 제출 시각을 저장합니다. 페이지가 다시 열리면:

- 제출 전: 같은 장면의 설정부터 다시 준비
- 제출 후: 기존 진행 카드와 새 미디어를 찾아 기존 생성 추적

중복 결과를 피하려면 새로고침 직후 수동으로 프롬프트를 다시 보내지 말고 잠시 상태를 확인하세요.

#### 작업이 실패했지만 다음 작업으로 넘어가지 않음

- CAPTCHA·로그인·quota·크레딧·DevTools 오류라면 정상 동작입니다. 사용자 조치 후 실패 작업을 다시 실행하세요.
- 일반 장면 오류라면 자동 재시도 1회를 기다립니다.
- 캐릭터 생성 실패는 캐릭터 매핑이 필요한 경우가 많으므로 캐릭터 카드의 오류 원인을 확인하세요.
- 카드에 최종 실패가 남아 있으면 **실패 작업 다시 실행**을 사용합니다.

#### 일일 한도 또는 크레딧 부족

1. 오류 메시지에서 한도에 도달한 모델을 확인합니다.
2. 사용 가능한 다른 모델로 변경하거나 한도가 회복될 때까지 기다립니다.
3. **실패 작업 다시 실행**을 누릅니다.

계정 한도와 결제 상태를 확장이 변경하거나 우회하지는 않습니다.

#### CAPTCHA 또는 로그인 확인

1. 큐를 중단합니다.
2. Flow 탭에서 CAPTCHA·로그인·사람 확인을 직접 완료합니다.
3. Flow 프로젝트 화면으로 돌아옵니다.
4. **연결 확인**을 누릅니다.
5. 실패 작업을 다시 실행합니다.

확장은 CAPTCHA를 자동 통과시키지 않습니다.

#### DevTools 충돌

Flow 탭에 DevTools가 열려 있으면 `chrome.debugger`를 사용할 수 없습니다.

1. 해당 Flow 탭의 DevTools를 닫습니다.
2. 확장 프로그램을 새로고침합니다.
3. Flow 탭을 새로고침합니다.
4. 연결 확인 후 실패 작업을 다시 실행합니다.

#### 대기 중 숫자가 예상과 다름

전체 작업에는 캐릭터 작업과 이미지 작업이 모두 포함됩니다. 캐릭터가 이미 완료되었으면 완료 작업 수에는 포함되지만 남은 작업에는 포함되지 않습니다. 생성 이미지 수는 작업 수가 아니라 실제로 확인된 결과 이미지 수입니다.

#### `새로시작` 후에도 Flow 이미지가 남아 있음

**새로시작**은 확장의 큐와 입력 초안을 지우는 기능입니다. Flow 프로젝트에 이미 생성된 캐릭터·장면·인트로·썸네일 이미지를 삭제하지 않습니다.

#### 다운로드 카드 수가 실제 결과와 다름

다운로드는 현재 Flow의 **모든 미디어** 카드를 다시 스캔합니다. Flow 카드가 최신순으로 정렬되어 있으면 확장이 오래된 순서로 뒤집어 장면 번호에 연결합니다.

다운로드 전:

1. Flow에서 **모든 미디어** 화면을 엽니다.
2. 생성이 끝났는지 확인합니다.
3. 캐릭터·장면 카드가 의도한 순서로 표시되는지 확인합니다.
4. **전체 다운로드**를 누릅니다.

자동 생성 작업에 저장된 asset ID가 있으면 Flow가 실제로 반환한 카드 수(1장 또는 3~4장 포함)를 모두 사용합니다. 작업별 결과가 저장되지 않은 오래된 큐는 순서 기반 fallback으로 처리되며 다운로드 상태에 매핑 확인 경고가 표시됩니다.

#### 이미지가 다른 장면에 붙었을 때

1. 큐를 일시정지하거나 완료한 뒤 `이미지 매핑`에서 **Flow 목록 새로고침**을 누릅니다.
2. 각 Flow 이미지의 미리보기와 asset ID를 확인합니다.
3. 이미지 오른쪽 선택 상자에서 대상 장면·인트로·썸네일을 지정합니다.
4. 같은 이미지를 다른 작업에 지정하면 기존 매핑은 자동으로 해제됩니다. `미지정`을 선택하면 수동 매핑을 해제합니다.

수동 매핑은 자동 결과에 추가하거나 이동한 asset ID를 고정합니다. 다운로드 때는 자동 결과와 수동 매핑 결과를 중복 없이 함께 저장합니다.

장면 카드의 작은 `#1`, `#2` 결과 버튼에 마우스를 올리면 확대 미리보기가 표시됩니다. 잘못 자동 연결된 이미지는 카드의 `×` 버튼으로 해당 장면과의 연결만 해제할 수 있습니다. Flow에서 휴지통으로 이동했거나 현재 미디어 목록에서 사라진 결과는 `이미지 매핑`의 `Flow 목록에 없는 연결` 영역에 별도로 표시되며, 여기서 **연결 해제**를 누르면 남은 매핑 정보도 제거됩니다. 이 동작은 Flow 원본 이미지를 삭제하거나 복구하지 않습니다.

장면 간에 이미지를 옮길 때는 작은 `#1`, `#2` 썸네일을 원하는 장면 카드로 드래그해 놓으세요. 대상 카드가 보라색으로 강조되면 놓을 수 있고, 놓는 즉시 원래 장면의 자동·수동 연결이 해제되고 대상 장면에 고정됩니다. 이미지 생성 중에는 드래그 매핑을 변경할 수 없습니다.

매핑 순서가 중간부터 틀어진 경우에는 이미지 매핑의 **시작 이미지**와 **시작 장면**을 지정하세요. 예를 들어 `042`번 이미지와 `장면 022`를 선택한 뒤 **이후 번호대로 재지정**을 누르면, 선택한 장면부터 아래 작업의 기존 매핑을 초기화하고 실제 생성 장수(1장·3장·4장 등)를 기준으로 순서대로 다시 지정합니다. 선택한 시작점 이전의 매핑은 유지됩니다.

#### 이전 프로젝트의 매핑을 다시 사용할 때

1. Flow에서 이전 프로젝트를 엽니다. 주소의 `/project/{프로젝트ID}`가 저장 기록의 기준입니다.
2. 확장 패널을 열면 현재 Flow 프로젝트를 자동으로 확인하고, 저장된 캐릭터·매핑이 있으면 바로 복원합니다. 파일을 다시 드롭할 필요가 없습니다.
3. 자동 확인이 끝나기 전에 프로젝트를 바꿨다면 상단의 **Flow 연결됨 ↻** 버튼을 한 번 누릅니다. 이 버튼은 연결 확인과 프로젝트 기록 복원을 함께 수행합니다.
4. 같은 장면 프롬프트 파일을 다시 적용한 경우에도 `장면 번호`와 `인트로 번호`가 같은 작업에는 저장된 매핑이 자동으로 복원됩니다.
5. **Flow 목록 새로고침**을 한 번 눌러 현재 프로젝트에 실제로 남아 있는 이미지인지 확인합니다. Flow에서 삭제된 이미지는 기존처럼 연결 해제 대상으로 표시됩니다.

#### ZIP 다운로드 실패

1. Flow 로그인 상태를 확인합니다.
2. Flow 탭에서 CAPTCHA나 확인 페이지를 해결합니다.
3. 원본 이미지를 Flow 화면에서 직접 열 수 있는지 확인합니다.
4. Flow 프로젝트 탭을 새로고침합니다.
5. 사이드패널에서 다시 **전체 다운로드**를 누릅니다.

원본 하나마다 최대 30초를 기다리고 최대 3회 재시도합니다. 실패한 파일명과 원인은 다운로드 진행 영역에 남습니다.

#### 긴 프롬프트가 입력되지 않음

분석은 가능하더라도 Flow 입력 단계에서 너무 긴 텍스트가 거부될 수 있습니다. 장면을 여러 파일이나 여러 번의 큐로 나누어 실행하세요.

#### 창 최소화·화면 잠금·절전

- Chrome 창 최소화: 백그라운드 큐와 알람은 계속될 수 있으며, 숨김 Flow 페이지의 메뉴·버튼은 DOM 기반 fallback으로 조작합니다.
- Flow DOM 감시: 백그라운드 탭 throttling으로 완료 감지가 늦어질 수 있습니다.
- 화면 잠금: 사용자가 직접 잠그면 확장이 해제할 수 없습니다.
- MacBook 덮개 닫기: 확장이 막을 수 없습니다.
- Energy Saver/Memory Saver: Flow 페이지가 freeze되면 감시가 멈출 수 있습니다.

장시간 작업은 전원 연결, Flow 탭 표시 상태, 화면 잠금 해제 상태에서 실행하는 것이 안전합니다. 실행 중에는 `chrome.power` API로 유휴 절전 방지를 요청하지만, OS 강제 절전이나 탭 종료까지 막지는 않습니다.

### 11. 프로젝트 다운로드와 파일명 규칙

#### 다운로드 조건

실행 중인 큐가 없을 때 **전체 다운로드**를 사용할 수 있습니다. 일시정지 상태에서도 현재 Flow 미디어를 다운로드할 수 있습니다.

다운로드 과정:

1. Flow의 모든 미디어 카드와 캐릭터 원본 URL을 수집합니다.
2. 확장에 저장된 작업별 asset ID와 Flow 카드의 ID를 비교합니다.
3. 이미지 원본을 최대 2개씩 병렬로 가져옵니다.
4. 각 원본에 최대 30초 timeout과 최대 3회 재시도를 적용합니다.
5. 표준 ZIP 파일을 생성합니다.
6. 프로젝트 제목 기반 파일명으로 Chrome 다운로드를 요청합니다.

#### ZIP 파일명

Flow 프로젝트 제목이 다음과 같다면:

```text
015_종으로 팔려간 며느리 등의 점 세 개
```

다운로드 파일명은 다음과 같습니다.

```text
015_종으로_팔려간_며느리_등의_점_세_개.zip
```

규칙:

- 제목의 공백은 `_`
- 파일 시스템에서 사용할 수 없는 문자는 `_`
- Unicode 정규화 적용
- 제목은 최대 120자
- 날짜·시각을 파일명에 붙이지 않음
- 제목을 읽지 못하면 `Flow-project.zip`
- 같은 이름의 ZIP이 이미 있으면 Chrome이 충돌을 피하기 위해 파일명에 번호를 붙일 수 있음

#### ZIP 내부 구조

```text
015_종으로_팔려간_며느리_등의_점_세_개.zip
└── Scene_Images/
    ├── 001-01.jpeg
    ├── 001-02.jpeg
    ├── 002-01.jpeg
    ├── 002-02.jpeg
    ├── 002-03.jpeg
    ├── 002-04.jpeg
    ├── intro1-1.jpeg
    ├── intro1-2.jpeg
    ├── thumbnail-1.jpeg
    └── saebyeol.jpeg
```

파일명:

- 장면: `001-01.jpeg`, `001-02.jpeg`
- 장면 번호: 세 자리
- 장면 이미지 번호: 두 자리
- 인트로: `intro1-1.jpeg`, `intro2-1.jpeg`
- 썸네일: `thumbnail-1.jpeg`
- 캐릭터: Flow 등록 키 또는 표시 이름 기반

#### asset ID 매핑

생성 완료 시 작업별 결과 이미지의 `assetId`, 상세 URL, 원본 URL을 저장합니다. 다운로드할 때 다음 우선순위로 같은 이미지를 찾습니다.

1. asset ID
2. Flow 상세 URL
3. 원본 이미지 URL

따라서 실패 후 재생성되거나 Flow 카드 순서가 바뀌어도 저장된 ID가 있으면 장면 번호와 이미지 번호를 유지할 수 있습니다. 다만 Flow에서 카드가 아직 DOM에 나타나지 않았거나 원본 URL을 제공하지 않는 경우에는 해당 파일을 확인할 수 없습니다.

#### 부족한 카드와 추가 카드

- 결과 카드가 부족하면 확인 가능한 이미지만 ZIP에 저장합니다.
- 부족한 장면·인트로·썸네일·캐릭터는 다운로드 완료 메시지에 표시됩니다.
- 한 장면에 여러 장이 있으면 실제 결과 수만큼 `001-01`, `001-02`, `001-03`처럼 저장합니다.
- asset ID가 없는 오래된 작업만 순서 fallback을 사용하므로, 결과가 섞였으면 먼저 이미지 매핑을 지정하세요.

### 12. 동작 제한과 안전상 주의

- 확장은 Google Flow의 UI와 접근성 라벨에 의존합니다. Flow UI 변경 시 선택자 수정이 필요할 수 있습니다.
- 로그인, CAPTCHA, 계정 확인, 결제, 크레딧 충전, quota 우회를 대신하지 않습니다.
- 대기시간은 요청 빈도를 낮추지만 Google의 자동화 정책 준수를 보장하지 않습니다.
- 실제 이미지 생성은 Flow 계정의 크레딧과 일일 한도를 사용합니다.
- 이미 전송된 Flow 생성 요청은 **대기열 중단**으로 반드시 취소되지 않을 수 있습니다.
- 다운로드는 현재 Flow 프로젝트의 모든 미디어를 다시 스캔하므로, 확장 큐에 없는 이전 이미지가 포함될 수 있습니다.
- Flow 탭을 닫거나 프로젝트를 삭제하면 해당 작업을 이어서 감지할 수 없습니다.
- Chrome 확장 저장소를 삭제하면 큐 상태, 프로젝트별 캐릭터 이력, 입력 초안이 사라질 수 있습니다.
- ZIP 원본 수집은 로그인된 Flow 세션과 호스트 권한이 필요합니다.
- 자동화 중에는 DevTools를 해당 Flow 탭에 연결하지 마세요.

### 13. 파일별 역할

#### 사용자 화면

- `sidepanel.html`: 사이드패널의 실제 HTML 구조, 탭, 버튼, 입력, 상태 영역
- `sidepanel.css`: 사이드패널 레이아웃, 상태 색상, 진행률, 카드, 버튼 스타일
- `sidepanel.js`: 프롬프트 분석 호출, 상태 표시, 버튼 이벤트, 초안 저장, 큐 명령, 수동 복구, 다운로드 진행 표시

#### Chrome 확장 실행부

- `manifest.json`: Manifest V3 설정, 권한, 서비스 워커, 사이드패널, Flow 콘텐츠 스크립트 대상
- `background.js`: 서비스 워커. 영속 큐 상태, Flow 탭 탐색, debugger 입력 전달, 실행·대기·복구·재시도, 전원 유지, 다운로드 요청 담당
- `content.js`: Flow 탭 안에서 실행되는 콘텐츠 스크립트. 화면 전환, 입력, 캐릭터 등록, `@key` 애셋 참조, 생성 감시, 오류 감지, 미디어 URL·asset ID 수집 담당
- `offscreen.html`: 화면에 표시되지 않는 ZIP 생성 문서
- `offscreen.js`: 원본 이미지 fetch, timeout·재시도, ZIP Blob 생성과 해제 담당

#### 핵심 라이브러리

- `lib/queue-state.js`: 상태 초기화·정규화, 캐릭터 우선 작업 순서, 대기시간, 자동 재시도 한도, 실패 후 다음 작업 진행, reload 복구 메타데이터
- `lib/prompt-parser.js`: Flow 전용 문서, 인트로훅, Markdown, 라벨, 목록, 구분선, 일반 텍스트 분석
- `lib/download-manifest.js`: asset 중복 제거, 작업별 asset ID 매핑, ZIP 내부 파일명, 누락·초과 카드 계산
- `lib/zip-archive.js`: JPEG를 불필요하게 다시 압축하지 않는 표준 저장 방식 ZIP 작성기
- `lib/archive-result.js`: offscreen ZIP 생성 결과가 Blob URL과 이미지 개수를 갖는지 검증
- `lib/project-history.js`: 프로젝트 ID별 캐릭터 정의와 Flow 등록 키 이력 저장·정규화

#### 테스트

- `tests/queue-state.test.js`: 큐 순서, 상태, 대기, 재시도, 실패, 복구
- `tests/prompt-parser.test.js`: Flow/Markdown/인트로훅 파싱
- `tests/download-manifest.test.js`: asset 매핑과 ZIP 파일명·내부 경로
- `tests/zip-archive.test.js`: ZIP 포맷과 경로
- `tests/content-character-scan.test.js`: Flow 화면 탐색, 오류 감지, 생성 감시
- `tests/background-completion.test.js`: 백그라운드 완료·중단·실패 처리
- `tests/background-power.test.js`: 큐 실행 중 전원 유지
- `tests/background-project-history.test.js`: 프로젝트별 캐릭터 이력
- `tests/sidepanel-disabled-reason.test.js`: UI 비활성 이유, 자동 연결 확인, 초안 초기화, 작업 카드
- `tests/sidepanel-manual-controls.test.js`: 수동 복구 UI
- `tests/offscreen-download.test.js`: 원본 fetch와 다운로드 재시도

### 14. 개발자용 검증

Node.js 20 이상을 설치한 뒤 저장소 최상위 폴더에서 실행합니다.

```bash
npm install
npm run check
```

`npm run check`는 다음을 수행합니다.

1. `background.js`, `content.js`, `sidepanel.js`, `offscreen.js` 문법 검사
2. Node 내장 테스트 러너로 전체 회귀 테스트 실행

현재 버전은 `0.9.16`이며, 확장 프로그램 배포 전 `manifest.json`, `package.json`, `package-lock.json`의 버전을 함께 확인해야 합니다.
